# US-35 · Taxa da maquininha nas doações em dinheiro (5 SP)

> Como coordenadora do financeiro, eu quero que a doação recebida pela maquininha desconte a taxa, como a venda, para que o total de doações no sistema seja o que de fato cai na conta do Instituto.

**Tipo:** user story · **Implementa:** Mateus · **Revisa:** Bibiana · **Branch:** `us-35-taxa-nas-doacoes` · **Depende de:** US-32 (na `main` desde 06/11) e TS-05 · **PR pronto:** terça 10/11, 18h · **Merge:** terça 10/11, à noite, depois do `db push`

**Estimativa:** 5 SP, como proposto em 30/10. Muda a tabela e a view das doações em dinheiro, o formulário, a lista, o relatório consolidado e a exportação.

## Critérios de aceitação

- [ ] A doação em dinheiro pode informar por onde o dinheiro chegou: sem maquininha (espécie ou transferência) ou um banco ou maquininha da lista, com a forma (Pix, débito, crédito à vista ou parcelado) e, no débito da PagBank, a bandeira
- [ ] O líquido é calculado pelo banco de dados, com a taxa em vigor da US-32 na hora do registro, e fica gravado com a taxa usada; sem maquininha, o líquido é o próprio valor; sem taxa cadastrada, aparece "taxa não cadastrada"
- [ ] A lista de doações em dinheiro mostra o líquido; o relatório consolidado e a exportação mostram bruto e líquido, de vendas e de doações (resposta da Nílian: "os dois, de preferência")
- [ ] Banco "Doação Solutions" (plataforma do site) disponível só para doações, sem taxa até a Nílian informar; não aparece na nova venda
- [ ] Doações antigas ficam com líquido igual ao valor; recibo e atendimentos continuam pelo valor doado (bruto) até o Instituto responder a pergunta 8
- [ ] Testes de fumaça e de acesso passam

## O que já existe

- `donations_cash` guarda valor, origem (PIX, Dinheiro, Transferência, Site, Outro), frequência, evento e campanha. Não tem forma de pagamento, maquininha nem líquido.
- A US-32 criou `taxas_de_cartao` e a view `taxas_em_vigor` (taxa por banco, forma, parcelado e bandeira), e as funções `pedeBandeira`, `rotuloDaCombinacao` e `textoDaTaxa` em `lib/taxas.ts`. Na venda, o líquido é calculado no servidor do Next (`valorLiquido`).
- **Resposta da Nílian (30/10):** as doações entram "por cartão cadastrado no site antigo (hoje o site usa a Doação Solutions) e por Pix na chave da PagBank, sem taxa (exemplo: o Natalenço)"; no relatório, "os dois [bruto e líquido], de preferência; se não der, o líquido".

## Decisões

- **O banco calcula o líquido da doação**, por gatilho, e grava a taxa usada (`taxa`) e o líquido (`net_amount`). Ninguém manda o líquido pelo formulário. Se a coordenação corrigir o valor depois (US-04b), o líquido é refeito com a mesma taxa gravada; se trocar a maquininha ou a forma, a taxa é buscada de novo.
- **Sem maquininha** (espécie, transferência, depósito): taxa vazia e líquido igual ao valor.
- **Origem continua** como está (PIX, Dinheiro, Transferência, Site, Outro): diz de onde veio a doação. A maquininha diz por onde o dinheiro entrou e quanto ficou.
- **Banco só para doações:** a coluna nova `banks.uso` (`vendas`, `doacoes` ou `ambos`) separa a "Doação Solutions", que não pode aparecer na venda do brechó. Todos os bancos de hoje ficam `ambos`.
- **Pix da PagBank:** fica com a taxa em vigor (0,19% desde a US-32). A Nílian disse que o Pix das doações na chave da PagBank não tem taxa; a pergunta "0,19% ou sem taxa" está em aberto desde 03/11. Se ela confirmar "sem taxa", a coordenação cadastra 0% em Relatórios · Taxas e vale para vendas e doações novas.
- **Recibo e atendimentos usam o bruto** até o Instituto responder (pergunta 8 da mensagem de 06/11). Mudar depois é trocar `amount` por `net_amount` em dois lugares.

```sql
-- US-35 · Taxa da maquininha nas doações em dinheiro
-- A doação pode dizer por onde o dinheiro entrou (banco ou maquininha, forma e,
-- no débito da PagBank, bandeira). O banco de dados busca a taxa em vigor
-- (US-32), grava a taxa usada e calcula o líquido. Sem maquininha, líquido = valor.

-- ─────────────────────────────────────────
-- 1. Banco só de doação: a plataforma do site (Doação Solutions) não pode
--    aparecer na venda do brechó. Os bancos de hoje servem para as duas.
-- ─────────────────────────────────────────

alter table public.banks
  add column if not exists uso text not null default 'ambos' check (uso in ('vendas', 'doacoes', 'ambos'));

insert into public.banks (name, type, uso) values ('Doação Solutions', 'card', 'doacoes')
on conflict (name) do nothing;

-- ─────────────────────────────────────────
-- 2. Colunas novas na doação em dinheiro. A combinação segue as regras da
--    tabela de taxas: parcelado só no crédito, bandeira só no débito.
-- ─────────────────────────────────────────

alter table public.donations_cash
  add column if not exists bank_id    uuid references public.banks(id) on delete restrict,
  add column if not exists forma      text check (forma in ('pix', 'debit', 'credit')),
  add column if not exists parcelado  boolean not null default false,
  add column if not exists bandeira   text check (bandeira in ('visa_master', 'outras')),
  add column if not exists taxa       numeric(5,2),
  add column if not exists net_amount numeric;

alter table public.donations_cash
  add constraint donations_cash_forma_com_banco check ((bank_id is null) = (forma is null)),
  add constraint donations_cash_parcelado_no_credito check (forma = 'credit' or parcelado = false),
  add constraint donations_cash_bandeira_no_debito check (bandeira is null or forma = 'debit');

-- Doações de antes desta story: sem maquininha, líquido igual ao valor.
update public.donations_cash set net_amount = amount where bank_id is null and net_amount is null;

-- ─────────────────────────────────────────
-- 3. Líquido calculado pelo banco de dados. Quem chama não escolhe taxa nem
--    líquido. Sem security definer: a taxa é lida com as permissões de quem
--    registra (a equipe lê as taxas, US-32).
-- ─────────────────────────────────────────

create or replace function public.calcular_liquido_da_doacao()
returns trigger
language plpgsql
set search_path = ''
as $$
begin
  if new.bank_id is null then
    new.forma := null;
    new.parcelado := false;
    new.bandeira := null;
    new.taxa := null;
  elsif tg_op = 'INSERT'
     or new.bank_id   is distinct from old.bank_id
     or new.forma     is distinct from old.forma
     or new.parcelado is distinct from old.parcelado
     or new.bandeira  is distinct from old.bandeira then
    select t.taxa into new.taxa
      from public.taxas_em_vigor t
     where t.bank_id = new.bank_id
       and t.forma = new.forma
       and t.parcelado = new.parcelado
       and coalesce(t.bandeira, '') = coalesce(new.bandeira, '');
    -- Sem linha: taxa fica nula ("taxa não cadastrada").
    if not found then
      new.taxa := null;
    end if;
  else
    -- Só o valor (ou outro campo) mudou: vale a taxa gravada no registro.
    new.taxa := old.taxa;
  end if;

  new.net_amount := case
    when new.bank_id is null then new.amount
    when new.taxa is null then null
    else round(new.amount * (1 - new.taxa / 100), 2)
  end;
  return new;
end;
$$;

create trigger liquido_da_doacao
  before insert or update on public.donations_cash
  for each row execute function public.calcular_liquido_da_doacao();

-- ─────────────────────────────────────────
-- 4. A view das doações em dinheiro passa a trazer maquininha, taxa e líquido.
--    Recriada, como na US-12 e na US-13, com security_invoker.
-- ─────────────────────────────────────────

drop view if exists public.donations_cash_view;
create view public.donations_cash_view
with (security_invoker = true) as
select
  d.id,
  d.client_id,
  d.donor_name,
  d.donor_phone,
  d.amount,
  d.frequency,
  d.donated_at,
  d.notes,
  d.created_at,
  coalesce(o.name, '') as origin,
  d.event_id,
  coalesce(e.name, '') as event_name,
  d.campaign_id,
  coalesce(c.name, '') as campaign_name,
  d.bank_id,
  coalesce(b.name, '') as bank_name,
  d.forma,
  d.parcelado,
  d.bandeira,
  d.taxa,
  d.net_amount
from public.donations_cash d
left join public.cash_origins o on o.id = d.origin_id
left join public.events e on e.id = d.event_id
left join public.campaigns c on c.id = d.campaign_id
left join public.banks b on b.id = d.bank_id;

revoke all on public.donations_cash_view from anon;
grant select on public.donations_cash_view to authenticated;
```

// US-35 · A forma escolhida no formulário de doação: o mesmo vocabulário da tela de taxas.
export const FORMAS_DA_DOACAO = {
  pix: { forma: 'pix', parcelado: false, tipoDoBanco: 'pix', rotulo: 'Pix' },
  debit: { forma: 'debit', parcelado: false, tipoDoBanco: 'card', rotulo: 'Débito' },
  credit_avista: { forma: 'credit', parcelado: false, tipoDoBanco: 'card', rotulo: 'Crédito à vista' },

} as const

export type FormaDaDoacao = keyof typeof FORMAS_DA_DOACAO

// "PagBank · Crédito à vista · 3,19%", para a lista e a exportação.
export function textoDoRecebimento(d: { bank_name?: string; forma?: string | null; parcelado?: boolean; bandeira?: string | null; taxa?: number | null }): string {
  if (!d.bank_name) return 'Sem maquininha'
  const combinacao = rotuloDaCombinacao({ forma: d.forma ?? '', parcelado: d.parcelado ?? false, bandeira: d.bandeira ?? null })
  return d.taxa === null || d.taxa === undefined
    ? `${d.bank_name} · ${combinacao} · taxa não cadastrada`
    : `${d.bank_name} · ${combinacao} · ${textoDaTaxa(Number(d.taxa))}`
}

  const { data: origem } = await caixa.from('cash_origins').select('id').eq('name', 'PIX').single()
