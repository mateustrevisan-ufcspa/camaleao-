# US-39 · Agradecimento enviado também pelo caixa (8 SP)

> Como pessoa do caixa, eu quero enviar o agradecimento com um clique, como a coordenação, para que quem atende o apoiador no dia a dia possa agradecer.

**Tipo:** user story · **Implementa:** Alissa · **Revisa:** Laís · **Branch:** `us-39-agradecimento-pelo-caixa` · **Depende de:** US-21a e US-36 (na `main`), US-04b (colunas `deleted_at`, integrada na terça) · **PR pronto:** quinta 19/11, 18h · **Merge:** quinta 19/11, à noite

**Origem:** resposta 3 da Flávia (09/11): a coordenação **e a Ana** (perfil caixa) enviam o agradecimento, e a mensagem pode trazer o número de atendimentos. Decisão de 09/11: a US-21a entrou só com a coordenação; o caixa é esta story.

**Estimativa:** o cartão foi proposto com 5 SP no planejamento de 15/11. Ao escrever o guia, passou para **8 SP**: o caixa não lê as vendas e doações do mês, nem o telefone completo, nem a aprovação do termo, então a lista inteira passa a vir de uma função do banco (que a US-41 reaproveita para o semanal e o anual).

## Por que pede desenho próprio

Para montar a lista do mês, a US-21a lê `sales_view`, `donations_cash_view` e `donations_items` do mês inteiro, o telefone pela `clients_view`, e as aprovações do termo e os agradecimentos. O caixa:

- só lê vendas e doações em dinheiro **do dia** (`balcao_le_desde`, US-23 e US-28);
- vê o telefone **mascarado** (SEC-05);
- não lê `aprovacoes_do_termo`, `agradecimentos` nem `destinatarios_do_agradecimento` (US-21a).

Dar essa leitura ao caixa desfaria a SEC-05. O desenho: **a lista e o registro passam a ser funções do banco** (`security definer`), que devolvem só o necessário. A lista não traz contato nenhum, só se a pessoa tem WhatsApp ou e-mail válido. O contato só sai no clique de agradecer, depois que o banco registrou o agradecimento (um por pessoa e por período), e só o do canal escolhido.

## Critérios de aceitação

- [ ] Caixa e coordenação abrem Clientes · Agradecimentos; a voluntária, não
- [ ] A lista do mês é a mesma da US-21a (quem contribuiu, total, atendimentos, peças, situação), montada pela função `pessoas_para_agradecer`, sem telefone nem e-mail
- [ ] Só a coordenação vê e usa o formulário de aprovação do termo
- [ ] O botão registra o agradecimento no banco e só então abre o WhatsApp ou o e-mail com a mensagem pronta; o contato vem do banco nesse momento
- [ ] O banco recusa: quem não autorizou um termo aprovado; quem não contribuiu no período; o segundo agradecimento no mesmo período; canal sem contato válido
- [ ] Quem autorizou um termo que não vale (US-36) aparece com "Autorizou um termo que não vale (veja a ficha)"
- [ ] O caixa continua sem ler `agradecimentos`, `aprovacoes_do_termo` e os lançamentos de outros dias pela API
- [ ] Testes de acesso e de fumaça passam

## Decisões

- **Um caminho só:** coordenação e caixa usam as mesmas funções; a página não lê mais as tabelas direto.
- **O texto da mensagem é montado na página** (como hoje) e vai junto no clique. O servidor só monta o link com o contato que o banco devolveu. O texto não é dado sensível, e a pessoa ainda pode editar no WhatsApp antes de enviar.
- **O contato sai uma vez por pessoa e por período**, e o agradecimento guarda quem enviou (`enviado_por`). É o mínimo para mandar a mensagem: quem envia pelo WhatsApp vê o número de qualquer jeito.
- **Período em texto, com intervalo calculado pelo banco** (`intervalo_do_periodo`): `AAAA-MM` e `AAAA` agora; a US-41 acrescenta a semana (`AAAA-Snn`).
- **`souCaixaOuCoordenacao()`** nasce aqui, em `lib/store.ts` (a US-37, na sexta, usa a mesma).

## Parte A · Migração `supabase/migrations/20261119090000_agradecimento_pelo_caixa.sql`

```sql
-- US-39 · Agradecimento enviado também pelo caixa
-- A lista e o registro do agradecimento passam a ser funções security definer,
-- para caixa e coordenação. A lista não traz contato; o contato do canal escolhido
-- só sai no registro, um por pessoa e por período.

-- ─────────────────────────────────────────
-- 1. O intervalo de um período, em São Paulo: AAAA-MM (mês) ou AAAA (ano).
--    A US-41 acrescenta a semana.
-- ─────────────────────────────────────────

create or replace function public.intervalo_do_periodo(p_periodo text, out desde timestamptz, out ate timestamptz)
language plpgsql
stable
set search_path = ''
as $$
declare
  v_inicio date;
  v_fim    date;
begin
  if p_periodo ~ '^\d{4}-(0[1-9]|1[0-2])$' then
    v_inicio := to_date(p_periodo || '-01', 'YYYY-MM-DD');
    v_fim := (v_inicio + interval '1 month')::date;
  elsif p_periodo ~ '^\d{4}$' then
    v_inicio := to_date(p_periodo || '-01-01', 'YYYY-MM-DD');
    v_fim := (v_inicio + interval '1 year')::date;
  else
    raise exception 'período inválido' using errcode = '22023';
  end if;
  desde := v_inicio::timestamp at time zone 'America/Sao_Paulo';
  ate := v_fim::timestamp at time zone 'America/Sao_Paulo';
end;
$$;

-- ─────────────────────────────────────────
-- 2. Quem contribuiu no período, com as somas da US-21a e a situação da
--    mensagem. Sem telefone nem e-mail: só se há contato válido para cada canal.
--    Doação pela maquininha conta atendimentos pelo líquido (US-35, pergunta 8).
-- ─────────────────────────────────────────

create or replace function public.pessoas_para_agradecer(p_periodo text)
returns table (
  client_id uuid,
  nome text,
  compras numeric,
  doacoes numeric,
  doacoes_para_atendimentos numeric,
  pecas int,
  pode_receber boolean,
  termo_que_nao_vale boolean,
  agradecida_em timestamptz,
  canal text,
  tem_whatsapp boolean,
  tem_email boolean
)
language plpgsql
stable
security definer
set search_path = ''
as $$
#variable_conflict use_column
declare
  v_desde timestamptz;
  v_ate   timestamptz;
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação agradecem' using errcode = '42501';
  end if;
  select i.desde, i.ate into v_desde, v_ate from public.intervalo_do_periodo(p_periodo) i;

  return query
  with vendas as (
    select s.client_id, sum(s.amount) as total
      from public.sales s
     where s.deleted_at is null and s.client_id is not null and s.sold_at >= v_desde and s.sold_at < v_ate
     group by s.client_id
  ), dinheiro as (
    select d.client_id,
           sum(d.amount) as total,
           sum(case
                 when coalesce(d.forma in ('debit', 'credit') and b.uso <> 'doacoes', false) and d.net_amount is not null
                   then d.net_amount
                 else d.amount
               end) as para_atendimentos
      from public.donations_cash d
      left join public.banks b on b.id = d.bank_id
     where d.deleted_at is null and d.client_id is not null and d.donated_at >= v_desde and d.donated_at < v_ate
     group by d.client_id
  ), itens as (
    select i.client_id,
           sum(case
                 when i.aproveitadas is not null then i.aproveitadas + coalesce(i.redoadas, 0) + coalesce(i.descarte, 0)
                 else coalesce(i.quantity, 0)
               end)::int as pecas
      from public.donations_items i
     where i.deleted_at is null and i.client_id is not null and i.donated_at >= v_desde and i.donated_at < v_ate
     group by i.client_id
  ), ids as (
    select v.client_id from vendas v
    union select d.client_id from dinheiro d
    union select i.client_id from itens i
  ), podem as (
    select x.client_id from public.destinatarios_do_agradecimento x
  ), autorizaram as (
    select r.client_id from public.message_recipients r
  )
  select
    c.id,
    c.name,
    coalesce(v.total, 0),
    coalesce(d.total, 0),
    coalesce(d.para_atendimentos, 0),
    coalesce(it.pecas, 0),
    (c.id in (select client_id from podem)),
    (c.id in (select client_id from autorizaram) and c.id not in (select client_id from podem)),
    a.enviado_em,
    a.canal,
    regexp_replace(coalesce(c.phone, ''), '\D', '', 'g') ~ '^(\d{10,11}|55\d{10,11})$',
    coalesce(c.email, '') ~ '^[^\s@]+@[^\s@]+\.[^\s@]+$'
  from ids
  join public.clients c on c.id = ids.client_id
  left join vendas v on v.client_id = c.id
  left join dinheiro d on d.client_id = c.id
  left join itens it on it.client_id = c.id
  left join public.agradecimentos a on a.client_id = c.id and a.periodo = p_periodo;
end;
$$;

-- ─────────────────────────────────────────
-- 3. Registrar e receber o contato do canal escolhido. O gatilho da US-21a
--    confere o termo aprovado (42501) e o unique, o segundo do período (23505).
-- ─────────────────────────────────────────

create or replace function public.registrar_agradecimento(p_client_id uuid, p_periodo text, p_canal text)
returns text
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_desde   timestamptz;
  v_ate     timestamptz;
  v_phone   text;
  v_email   text;
  v_contato text;
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação agradecem' using errcode = '42501';
  end if;
  if p_canal not in ('whatsapp', 'email') then
    raise exception 'canal inválido' using errcode = '22023';
  end if;
  select i.desde, i.ate into v_desde, v_ate from public.intervalo_do_periodo(p_periodo) i;

  if not (
    exists (select 1 from public.sales s where s.client_id = p_client_id and s.deleted_at is null and s.sold_at >= v_desde and s.sold_at < v_ate)
    or exists (select 1 from public.donations_cash d where d.client_id = p_client_id and d.deleted_at is null and d.donated_at >= v_desde and d.donated_at < v_ate)
    or exists (select 1 from public.donations_items i where i.client_id = p_client_id and i.deleted_at is null and i.donated_at >= v_desde and i.donated_at < v_ate)
  ) then
    raise exception 'esta pessoa não contribuiu neste período' using errcode = '22023';
  end if;

  select c.phone, c.email into v_phone, v_email from public.clients c where c.id = p_client_id;
  if p_canal = 'whatsapp' then
    v_contato := v_phone;
    if regexp_replace(coalesce(v_contato, ''), '\D', '', 'g') !~ '^(\d{10,11}|55\d{10,11})$' then
      raise exception 'sem telefone com DDD na ficha' using errcode = '22023';
    end if;
  else
    v_contato := v_email;
    if coalesce(v_contato, '') !~ '^[^\s@]+@[^\s@]+\.[^\s@]+$' then
      raise exception 'sem e-mail válido na ficha' using errcode = '22023';
    end if;
  end if;

  insert into public.agradecimentos (client_id, periodo, canal, term_version)
  values (p_client_id, p_periodo, p_canal, '');

  return v_contato;
end;
$$;

-- ─────────────────────────────────────────
-- 4. A versão atual do termo foi aprovada? Para o caixa, que não lê as aprovações.
-- ─────────────────────────────────────────

create or replace function public.termo_aprovado(p_versao text)
returns boolean
language sql
stable
security definer
set search_path = ''
as $$
  select public.eh_equipe() and exists (select 1 from public.aprovacoes_do_termo a where a.versao = p_versao)
$$;

revoke execute on function public.intervalo_do_periodo(text) from public, anon;
grant execute on function public.intervalo_do_periodo(text) to authenticated;
revoke execute on function public.pessoas_para_agradecer(text) from public, anon;
grant execute on function public.pessoas_para_agradecer(text) to authenticated;
revoke execute on function public.registrar_agradecimento(uuid, text, text) from public, anon;
grant execute on function public.registrar_agradecimento(uuid, text, text) to authenticated;
revoke execute on function public.termo_aprovado(text) from public, anon;
grant execute on function public.termo_aprovado(text) to authenticated;
```

Pontos de atenção:

- `#variable_conflict use_column`: as colunas do `returns table` (`client_id`, `nome`...) viram variáveis dentro da função; sem a diretiva, `client_id` nas consultas dá "column reference is ambiguous".
- Dentro da função `security definer`, as views `security_invoker` (`destinatarios_do_agradecimento`, `message_recipients`) rodam com o dono da função e não filtram pela coordenação. É de propósito: a função já conferiu o perfil e não devolve o conteúdo das views, só `true` ou `false`.
- O gatilho `carimbo_do_agradecimento` grava `enviado_por = auth.uid()`: dentro da função, continua sendo quem clicou.
- Os nomes das colunas de `donations_items` (`quantity`, `aproveitadas`, `redoadas`, `descarte`, `deleted_at`, `donated_at`) e de `banks.uso` (US-35) estão nas migrações `20260611003900_init.sql`, `20261102110000_editar_e_excluir_item.sql`, `20261103090000_contagem_da_triagem.sql` e `20261109100000_taxa_nas_doacoes.sql`; confira antes de rodar.

```ts
// US-39 · Quem contribuiu no período, pela função do banco (caixa e coordenação).
// periodo: AAAA-MM (mês) ou AAAA (ano); a US-41 acrescenta AAAA-Snn (semana).
export async function getPessoasParaAgradecer(periodo: string): Promise<{
  pessoas: PessoaParaAgradecer[]
  valorDoAtendimento: number
  termoAprovado: boolean
}> {
  const supabase = await createClient()
  const [lista, aprovado, valorDoAtendimento] = await Promise.all([
    supabase.rpc('pessoas_para_agradecer', { p_periodo: periodo }),
    supabase.rpc('termo_aprovado', { p_versao: TERMO_MENSAGENS.versao }),
    getValorDoAtendimento(),
  ])
  const erro = lista.error ?? aprovado.error
  if (erro) throw new Error(erro.message)

  const pessoas = ((lista.data ?? []) as Record<string, unknown>[]).map((r): PessoaParaAgradecer => {
    const compras = Number(r.compras)
    const doacoes = Number(r.doacoes)
    return {
      id: r.client_id as string,
      name: r.nome as string,
      compras: round2(compras),
      doacoes: round2(doacoes),
      pecas: Number(r.pecas),
      total: round2(compras + doacoes),
      paraAtendimentos: round2(compras + Number(r.doacoes_para_atendimentos)),
      podeReceber: r.pode_receber === true,
      termoQueNaoVale: r.termo_que_nao_vale === true,
      agradecidaEm: (r.agradecida_em as string | null) ?? null,
      canal: (r.canal as PessoaParaAgradecer['canal']) ?? null,
      temWhatsApp: r.tem_whatsapp === true,
      temEmail: r.tem_email === true,
    }
  })
  return {
    pessoas: pessoas.sort((a, b) => b.total - a.total || b.pecas - a.pecas || a.name.localeCompare(b.name, 'pt-BR')),
    valorDoAtendimento,
    termoAprovado: aprovado.data === true,
  }
}

// Registra no banco e devolve o contato do canal escolhido (US-39).
export async function addAgradecimento(clientId: string, periodo: string, canal: 'whatsapp' | 'email'): Promise<string> {
  const supabase = await createClient()
  const { data, error } = await supabase.rpc('registrar_agradecimento', { p_client_id: clientId, p_periodo: periodo, p_canal: canal })
  if (error) throw Object.assign(new Error(error.message), { code: error.code })
  return data as string
}
```

## Parte D · `actions/agradecimentos.ts`

```ts
'use server'

import { revalidatePath } from 'next/cache'
import { addAgradecimento, addAprovacaoDoTermo, souCaixaOuCoordenacao, souCoordenacao } from '@/lib/store'
import { ASSUNTO_DO_AGRADECIMENTO, linkDoEmail, linkDoWhatsApp } from '@/lib/mensagens'
import { TERMO_MENSAGENS } from '@/lib/termo-mensagens'
import { brTodayStr } from '@/lib/utils'

const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i
const PERIODO = /^\d{4}(-(0[1-9]|1[0-2]))?$/

// US-39 · Caixa e coordenação. O banco registra e devolve o contato; o link é montado aqui.
export async function registrarAgradecimento(
  clientId: string, periodo: string, canal: string, texto: string
): Promise<{ error: string } | { link: string }> {
  if (!(await souCaixaOuCoordenacao())) return { error: 'Só o caixa e a coordenação enviam agradecimentos.' }
  const mensagem = String(texto ?? '').trim().slice(0, 1500)
  if (!UUID.test(clientId) || !PERIODO.test(periodo) || (canal !== 'whatsapp' && canal !== 'email') || !mensagem) {
    return { error: 'Agradecimento inválido.' }
  }
  let contato: string
  try {
    contato = await addAgradecimento(clientId, periodo, canal)
  } catch (e) {
    const codigo = (e as { code?: string }).code
    if (codigo === '23505') return { error: 'Esta pessoa já foi agradecida neste período.' }
    if (codigo === '42501') return { error: 'Esta pessoa não autorizou mensagens com um termo aprovado pelo Instituto.' }
    if (codigo === '22023') return { error: 'Não deu para agradecer: confira o contato na ficha e se a pessoa contribuiu neste período.' }
    console.error('registrarAgradecimento error:', e)
    return { error: 'Não foi possível registrar o agradecimento. Tente novamente.' }
  }
  const link = canal === 'whatsapp' ? linkDoWhatsApp(contato, mensagem) : linkDoEmail(contato, ASSUNTO_DO_AGRADECIMENTO, mensagem)
  revalidatePath('/clientes/agradecimentos')
  // O banco já conferiu o contato; sem link aqui, só se a regra de lá e a de lib/mensagens divergirem.
  return link ? { link } : { error: 'Agradecimento registrado, mas o contato não serve para este canal. Confira a ficha.' }
}
```

## Parte E · Botão: `components/clients/botao-de-agradecer.tsx`

```tsx
'use client'

import { useState, useTransition } from 'react'
import { Mail, MessageCircle } from 'lucide-react'
import { registrarAgradecimento } from '@/actions/agradecimentos'

// Registra no banco antes de abrir o WhatsApp ou o e-mail: sem registro, nada sai.
// US-39: o contato vem do banco no clique (o caixa não tem o telefone na lista).
export function BotaoDeAgradecer({ clientId, periodo, texto, temWhatsApp, temEmail }: {
  clientId: string; periodo: string; texto: string; temWhatsApp: boolean; temEmail: boolean
}) {
  const [isPending, startTransition] = useTransition()
  const [erro, setErro] = useState<string | null>(null)

  function agradecer(canal: 'whatsapp' | 'email') {
    setErro(null)
    // A janela abre já no clique (senão o navegador bloqueia) e só recebe o link depois do registro.
    const janela = canal === 'whatsapp' ? window.open('about:blank', '_blank') : null
    if (janela) janela.opener = null
    startTransition(async () => {
      const r = await registrarAgradecimento(clientId, periodo, canal, texto)
      if ('error' in r) {
        janela?.close()
        setErro(r.error)
        return
      }
      if (janela) janela.location.href = r.link
      else window.location.href = r.link
    })
  }

  return (
    <div className="flex flex-col items-end gap-1">
      <div className="flex gap-2">
        {temWhatsApp && (
          <button type="button" disabled={isPending} onClick={() => agradecer('whatsapp')} className="chip bg-bg disabled:opacity-50">
            <MessageCircle size={11} /> WhatsApp
          </button>
        )}
        {temEmail && (
          <button type="button" disabled={isPending} onClick={() => agradecer('email')} className="chip bg-bg disabled:opacity-50">
            <Mail size={11} /> E-mail
          </button>
        )}
      </div>
      {erro && <span role="alert" className="text-xs text-coral">{erro}</span>}
    </div>
  )
}
```
