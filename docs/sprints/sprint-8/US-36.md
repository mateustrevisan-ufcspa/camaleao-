# US-36 · Termo de mensagens na versão 2026-11 (3 SP)

> Como coordenadora do Instituto, eu quero que o sistema use o texto do termo de mensagens que o Instituto aprovou, para que cada autorização registrada valha para o agradecimento.

**Tipo:** user story · **Implementa:** Alissa · **Revisa:** Laís · **Branch:** `us-36-termo-2026-11` · **Depende de:** nada · **PR pronto:** segunda 16/11, 18h · **Merge:** segunda 16/11, à noite (sem migração)

**Prioridade:** primeiro item de produto da sprint. Precisa estar publicado antes do treinamento e do início do uso: até entrar, toda autorização registrada sai como `2026-10`.

**Origem:** resposta 1 (Flávia, 06/11): o Instituto não aprovou o texto de 15/10 e mandou um texto novo. Não entrou na US-21a (PR #69) nem nos ajustes (PR #81).

## Decisão (Mateus, 15/11)

**As autorizações registradas pela versão `2026-10` não valem para mensagens, e nenhum registro é alterado.** A `2026-10` nunca foi aprovada, e a `2026-11` acrescenta finalidades (promoções e prestação de contas). Na prática:

- a coordenação só consegue registrar a aprovação da versão atual (`TERMO_MENSAGENS.versao`), então a `2026-10` nunca entra em `aprovacoes_do_termo`;
- a view `destinatarios_do_agradecimento` (US-21a) já exige versão aprovada: quem autorizou pela `2026-10` fica de fora sem nenhuma mudança no banco;
- na ficha, quem autorizou pela `2026-10` aparece com um aviso e o botão para ler o termo novo e registrar de novo, numa linha nova de `message_consents` (o histórico fica).

**O texto não é mudado pela equipe.** Fica com o Mateus perguntar à Nílian se "agradecer suas doações" cobre as compras no brechó (o agradecimento mensal inclui compras, resposta 2). Se a resposta pedir outro texto, é outra versão, com nova aprovação.

- [ ] `docs/privacidade/termo-de-mensagens.md` com o texto novo e a linha da `2026-11` na tabela de versões; a `2026-10` fica registrada como "não aprovada, substituída"

- [ ] Testes de fumaça e de acesso passam

## Parte A · `lib/termo-mensagens.ts`

O arquivo inteiro passa a ser:

```ts
// Termo de autorização de mensagens (US-07).
// O texto que a pessoa ouviu fica identificado pela versão gravada junto da
// autorização. Mudou o texto? Crie uma versão nova aqui e registre a mudança em
// docs/privacidade/termo-de-mensagens.md. Nunca edite o texto de uma versão que
// já foi usada.
//
// US-36 · Versão 2026-11: texto enviado pela Flávia em 06/11 (resposta 1). A 2026-10
// não foi aprovada; as autorizações registradas por ela continuam no histórico,
// mas não valem para mensagens (decisão de 15/11).
export const TERMO_MENSAGENS = {
  versao: '2026-11',
  texto:
    'O Instituto Camaleão solicita seus contatos telefônicos (WhatsApp ou SMS) e/ou e-mail apenas com o objetivo de ' +
    'agradecer suas doações; avisar sobre campanhas, eventos e promoções; e fazer a prestação de contas sobre os ' +
    'atendimentos que oferecemos a quem está em tratamento oncológico. Seus dados serão utilizados apenas para este ' +
    'fim e não serão repassados a terceiros. Você pode retirar esta autorização quando quiser, em nossa sede ou pelos ' +
    'canais do Instituto, e deixa de receber mensagens a partir desse momento.',
} as const

// Versões que já foram usadas e não valem mais. Só para mostrar na ficha.
export const VERSOES_ANTERIORES: readonly string[] = ['2026-10']

export function termoVigente(versao: string | null | undefined): boolean {
  return versao === TERMO_MENSAGENS.versao
}
```

Confira caractere por caractere com o texto do `PROGRESSO.md` da Sprint 7 (é o texto da Flávia, só com o espaço depois de "terceiros." e sem o espaço duplo).

## Parte B · Ficha: `components/clients/message-consent.tsx`

1. Import: `import { TERMO_MENSAGENS, termoVigente } from '@/lib/termo-mensagens'`.
2. Troque o cálculo de `situacao` e os botões. Quem autorizou por outra versão vê o aviso e o botão de registrar no termo atual; "Retirar autorização" continua disponível.

```tsx
  const versaoAntiga = consent?.authorized === true && !termoVigente(consent.term_version)

  const situacao =
    consent === undefined ? 'Carregando...'
    : consent === null ? 'Ainda não foi perguntada. Sem autorização, não recebe mensagens.'
    : versaoAntiga ? `Autorizou em ${dia(consent.recorded_at)} pelo termo ${consent.term_version}, que não vale mais. Para receber mensagens, leia o termo atual para a pessoa e registre de novo.`
    : consent.authorized ? `Autorizou em ${dia(consent.recorded_at)} (termo ${consent.term_version}).`
    : `Retirou a autorização em ${dia(consent.recorded_at)}. Não recebe mensagens.`
```

E o bloco dos botões:

```tsx
      {consent !== undefined && !lendoTermo && (

          {consent?.authorized ? (
```

```ts
test('autorização pela 2026-10 não vale, mesmo com a versão atual aprovada', async () => {
  const p = await coordenacao.from('clients').insert({ name: `TESTE US-36 ${Date.now()}` }).select('id').single()
  await coordenacao.from('message_consents').insert({ client_id: p.data!.id, authorized: true, term_version: '2026-10' })
```

### `tests/fumaca/termo-de-mensagens.spec.ts` (arquivo novo)

```ts
// US-36 · Quem autorizou pela 2026-10 vê o aviso na ficha e registra pelo termo atual.
import { test, expect } from '@playwright/test'
import { entrar } from './apoio'
import { COORDENACAO, entrarNaApi } from '../acesso/apoio'
import { TERMO_MENSAGENS } from '../../lib/termo-mensagens'

test('autorização antiga: aviso e novo registro pela versão atual', async ({ page }) => {
  const { api } = await entrarNaApi(COORDENACAO)
  const nome = `Teste Termo ${Date.now()}`
  const { data: pessoa } = await api.from('clients').insert({ name: nome }).select('id').single()
  await api.from('message_consents').insert({ client_id: pessoa!.id, authorized: true, term_version: '2026-10' })

  await entrar(page)
  await page.goto('/clientes')
  await page.getByPlaceholder('Buscar cliente...').fill(nome)
  await page.getByText(nome).first().click()
  await expect(page.getByRole('heading', { name: nome })).toBeVisible()

  const cartao = page.getByTestId('autorizacao-de-mensagens')
  await expect(cartao.getByTestId('situacao-da-autorizacao')).toContainText('não vale mais')
  await cartao.getByRole('button', { name: 'Ler o termo atual e registrar' }).click()
  await expect(cartao).toContainText(`termo ${TERMO_MENSAGENS.versao}`)
  await expect(cartao).toContainText('promoções')
  await cartao.getByRole('button', { name: 'A pessoa autorizou' }).click()
  await expect(cartao.getByTestId('situacao-da-autorizacao')).toContainText(`(termo ${TERMO_MENSAGENS.versao})`)
})
```

A busca é a da lista de clientes (`components/clients/clients-list.tsx`, placeholder "Buscar cliente..."); clicar no nome abre a ficha, como em `tests/fumaca/ficha-contato.spec.ts`.
