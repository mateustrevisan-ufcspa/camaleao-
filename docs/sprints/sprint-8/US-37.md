# US-37 · Correção e cancelamento de dinheiro pelo balcão, em qualquer data (5 SP)

> Como pessoa do balcão, eu quero corrigir e cancelar vendas e doações em dinheiro de qualquer data, para que um erro de digitação seja corrigido sem depender da coordenação.

**Tipo:** user story · **Implementa:** Laís · **Revisa:** Bibiana · **Branch:** `us-37-balcao-corrige-dinheiro` · **Depende de:** US-04b (integrada na terça 17/11), SEC-04 e US-39 (`souCaixaOuCoordenacao`, integrada na quinta 19/11) · **PR pronto:** sexta 20/11, 18h · **Merge:** sexta 20/11, à noite

**Origem:** resposta 4 (Flávia em 06/11; Nílian de acordo em 09/11): coordenação e balcão corrigem e cancelam, em qualquer data, com espaço para o motivo. Motivo obrigatório no cancelamento (aceito pela Nílian em 09/11) e opcional na correção. Decisão de 09/11: a US-04b fez a coordenação; abrir ao balcão é esta story.

## O que pede (não é só trocar a condição)

- **Leitura:** o caixa só lê o que foi lançado hoje (`balcao_le_desde`, US-23 e US-28). Para corrigir uma doação de outro dia, ele precisa achar o lançamento e abrir o formulário, sem ganhar leitura geral das vendas e doações antigas.
- **Alteração:** a política de `update` exige que a linha passe também pela política de leitura. Abrir a política ao caixa não basta para linha de outro dia.
- **Motivo:** desde a US-04b, a correção já aceita sem motivo; o cancelamento continua pedindo.

Por isso o balcão corrige e cancela por **funções do banco** (`security definer`), que conferem o perfil e só devolvem o necessário: a lista de um dia escolhido e os campos da doação que vai ser corrigida. A coordenação passa a usar as mesmas funções, para ter um caminho só.

## Critérios de aceitação

- [ ] Nova tela Brechó · Corrigir lançamento (`/brecho/corrigir`), para caixa e coordenação: escolhe o dia (até hoje) e vê as vendas e as doações em dinheiro desse dia, pela data da venda ou da doação
- [ ] Em cada doação: "Corrigir" (formulário da US-04b, motivo opcional) e "Cancelar" (motivo obrigatório)
- [ ] Em cada venda: "Cancelar" (motivo obrigatório), com o aviso "para corrigir, cancele e registre de novo em Nova venda"
- [ ] O caixa corrige e cancela em qualquer data; a voluntária não abre a tela nem chama as funções
- [ ] O caixa continua sem ler vendas e doações de outros dias pela API (as listas normais não mudam)
- [ ] Toda correção e todo cancelamento entram em Relatórios · Alterações, com quem fez e o motivo, quando houver
- [ ] Testes de acesso e de fumaça passam

## Decisões

- **A lista é de um dia, e não uma busca livre.** O caixa normalmente sabe quando lançou. Uma busca por nome em todo o histórico daria ao balcão a leitura que a SEC-05 tirou. A função devolve só o dia pedido: tipo, hora, nome, valor e forma, sem telefone.
- **Corrigir pela função:** `corrigir_doacao_em_dinheiro(...)` faz o `update` com os mesmos campos do formulário da US-04b. Os gatilhos continuam valendo: o líquido é refeito (US-35) e a trilha registra (SEC-04), com `auth.uid()` de quem chamou.
- **Cancelar:** `cancelar_venda` e `cancelar_doacao_em_dinheiro` (US-04b) passam a aceitar o caixa.
- **A política de `update` da coordenação (US-04b) fica.** A tela usa a função; a política só serve à coordenação pela API.
- **Venda continua sem correção campo a campo** (decisão da US-04b): cancelar e registrar de novo, agora também pelo caixa.

## Parte A · Migração `supabase/migrations/20261120090000_balcao_corrige_dinheiro.sql`

```sql
-- US-37 · Correção e cancelamento de dinheiro pelo balcão, em qualquer data
-- O caixa não lê vendas e doações de outros dias (US-23 e US-28). Por isso corrige
-- e cancela por funções security definer, que conferem o perfil e devolvem só o
-- necessário. A coordenação usa as mesmas funções.

-- ─────────────────────────────────────────
-- 1. Cancelar: caixa e coordenação (era só a coordenação, US-04b).
-- ─────────────────────────────────────────

create or replace function public.cancelar_venda(p_id uuid, p_motivo text)
returns void
language plpgsql
security definer
set search_path = ''
as $$
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação cancelam venda' using errcode = '42501';
  end if;
  if length(btrim(coalesce(p_motivo, ''))) < 5 then
    raise exception 'informe o motivo do cancelamento' using errcode = '22023';
  end if;
  update public.sales
     set deleted_at = now(), deleted_by = auth.uid(), motivo_da_alteracao = left(btrim(p_motivo), 300)
   where id = p_id and deleted_at is null;
  if not found then
    raise exception 'venda não encontrada' using errcode = 'P0002';
  end if;
end;
$$;

create or replace function public.cancelar_doacao_em_dinheiro(p_id uuid, p_motivo text)
returns void
language plpgsql
security definer
set search_path = ''
as $$
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação cancelam doação em dinheiro' using errcode = '42501';
  end if;
  if length(btrim(coalesce(p_motivo, ''))) < 5 then
    raise exception 'informe o motivo do cancelamento' using errcode = '22023';
  end if;
  update public.donations_cash
     set deleted_at = now(), deleted_by = auth.uid(), motivo_da_alteracao = left(btrim(p_motivo), 300)
   where id = p_id and deleted_at is null;
  if not found then
    raise exception 'doação não encontrada' using errcode = 'P0002';
  end if;
end;
$$;

-- ─────────────────────────────────────────
-- 2. Os lançamentos de um dia, para corrigir. Pela data da venda ou da doação
--    (em São Paulo), e não pela data do lançamento. Sem telefone.
-- ─────────────────────────────────────────

create or replace function public.lancamentos_para_corrigir(p_dia date)
returns table (tipo text, id uuid, momento timestamptz, nome text, valor numeric, detalhe text)
language plpgsql
stable
security definer
set search_path = ''
as $$
declare
  v_desde timestamptz := p_dia::timestamp at time zone 'America/Sao_Paulo';
  v_ate   timestamptz := (p_dia + 1)::timestamp at time zone 'America/Sao_Paulo';
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação corrigem lançamentos' using errcode = '42501';
  end if;
  if p_dia is null or p_dia > (now() at time zone 'America/Sao_Paulo')::date then
    raise exception 'escolha um dia até hoje' using errcode = '22023';
  end if;
  return query
    select 'venda'::text, s.id, s.sold_at, s.customer_name, s.amount, coalesce(pm.label, '')
      from public.sales s
      left join public.payment_methods pm on pm.id = s.payment_method_id
     where s.deleted_at is null and s.sold_at >= v_desde and s.sold_at < v_ate
    union all
    select 'doacao'::text, d.id, d.donated_at, d.donor_name, d.amount, coalesce(o.name, '')
      from public.donations_cash d
      left join public.cash_origins o on o.id = d.origin_id
     where d.deleted_at is null and d.donated_at >= v_desde and d.donated_at < v_ate
    order by 3;
end;
$$;

-- ─────────────────────────────────────────
-- 3. A doação que vai ser corrigida: só os campos do formulário (US-04b).
-- ─────────────────────────────────────────

create or replace function public.doacao_para_corrigir(p_id uuid)
returns table (
  id uuid, donor_name text, amount numeric, donated_at timestamptz, origin text, frequency text,
  notes text, bank_id uuid, forma text, parcelado boolean, bandeira text
)
language plpgsql
stable
security definer
set search_path = ''
as $$
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação corrigem lançamentos' using errcode = '42501';
  end if;
  return query
    select d.id, d.donor_name, d.amount, d.donated_at, coalesce(o.name, 'Outro'), d.frequency,
           d.notes, d.bank_id, d.forma, d.parcelado, d.bandeira
      from public.donations_cash d
      left join public.cash_origins o on o.id = d.origin_id
     where d.id = p_id and d.deleted_at is null;
end;
$$;

-- ─────────────────────────────────────────
-- 4. Corrigir. Os gatilhos de donations_cash continuam: o líquido é refeito
--    (US-35) e a trilha registra quem fez (SEC-04, com auth.uid() de quem chamou).
--    Motivo opcional (resposta 4).
-- ─────────────────────────────────────────

create or replace function public.corrigir_doacao_em_dinheiro(
  p_id uuid,
  p_amount numeric,
  p_donated_at timestamptz,
  p_origin_id uuid,
  p_frequency text,
  p_notes text,
  p_bank_id uuid,
  p_forma text,
  p_parcelado boolean,
  p_bandeira text,
  p_motivo text
)
returns void
language plpgsql
security definer
set search_path = ''
as $$
begin
  if not public.eh_caixa_ou_coordenacao() then
    raise exception 'só o caixa e a coordenação corrigem doação em dinheiro' using errcode = '42501';
  end if;
  if p_amount is null or p_amount <= 0 then
    raise exception 'informe um valor maior que zero' using errcode = '22023';
  end if;
  if p_donated_at is null or p_donated_at > now() then
    raise exception 'a data da doação não pode ser depois de hoje' using errcode = '22023';
  end if;
  update public.donations_cash
     set amount = p_amount,
         donated_at = p_donated_at,
         origin_id = p_origin_id,
         frequency = p_frequency,
         notes = nullif(btrim(coalesce(p_notes, '')), ''),
         bank_id = p_bank_id,
         forma = p_forma,
         parcelado = coalesce(p_parcelado, false),
         bandeira = p_bandeira,
         motivo_da_alteracao = nullif(left(btrim(coalesce(p_motivo, '')), 300), '')
   where id = p_id and deleted_at is null;
  if not found then
    raise exception 'doação não encontrada' using errcode = 'P0002';
  end if;
end;
$$;

revoke execute on function public.lancamentos_para_corrigir(date) from public, anon;
grant execute on function public.lancamentos_para_corrigir(date) to authenticated;
revoke execute on function public.doacao_para_corrigir(uuid) from public, anon;
grant execute on function public.doacao_para_corrigir(uuid) to authenticated;
revoke execute on function public.corrigir_doacao_em_dinheiro(uuid, numeric, timestamptz, uuid, text, text, uuid, text, boolean, text, text) from public, anon;
grant execute on function public.corrigir_doacao_em_dinheiro(uuid, numeric, timestamptz, uuid, text, text, uuid, text, boolean, text, text) to authenticated;
```

export async function getDoacaoEmDinheiro(id: string): Promise<DoacaoEmDinheiroParaCorrigir | null> {
  const supabase = await createClient()
  const { data, error } = await supabase.rpc('doacao_para_corrigir', { p_id: id }).maybeSingle()
  if (error) throw new Error(error.message)
  return data ? ({ ...(data as DoacaoEmDinheiroParaCorrigir), amount: Number((data as { amount: number }).amount) }) : null
}

export async function updateDoacaoEmDinheiro(
  id: string,
  campos: {
    amount: number; donated_at: string; origin: string; frequency: 'monthly' | 'one_time'; notes: string | null
    bank_id: string | null; forma: 'pix' | 'debit' | 'credit' | null; parcelado: boolean; bandeira: 'visa_master' | 'outras' | null
    motivo_da_alteracao: string | null
  }
): Promise<void> {
  const supabase = await createClient()
  const { data: origem, error: erroOrigem } = await supabase.from('cash_origins').select('id').eq('name', campos.origin).single()
  if (erroOrigem) throw new Error(erroOrigem.message)
  const { error } = await supabase.rpc('corrigir_doacao_em_dinheiro', {
    p_id: id, p_amount: campos.amount, p_donated_at: campos.donated_at, p_origin_id: origem.id,
    p_frequency: campos.frequency, p_notes: campos.notes, p_bank_id: campos.bank_id, p_forma: campos.forma,
    p_parcelado: campos.parcelado, p_bandeira: campos.bandeira, p_motivo: campos.motivo_da_alteracao,
  })
  if (error) throw new Error(error.message)
}
