# US-13 · Doação vinculada a uma campanha (5 SP)

> Como coordenadora do Instituto, eu quero registrar doações destinadas a uma campanha específica, como Adapta ou Natalenço, para que eu saiba quanto cada campanha arrecadou e o quanto isso cobre o custo dela.

**Tipo:** user story · **Épico:** Doações reorganizadas · **Implementa:** Laís · **Revisa:** Mateus · **Branch:** `us-13-doacao-de-campanha` · **Depende de:** US-12 integrada (a migração de evento, a `donations_cash_view` com o evento e o campo de evento no formulário). As Partes E, F e G dependem da US-15, da US-17 e da US-18 na `main`. Acrescentada à Sprint 4 no replanejamento de 20/10.

## Critérios de aceitação

- [ ] Deve permitir cadastrar campanha com nome, período e custo estimado
- [ ] Deve registrar doação em dinheiro vinculada a uma campanha
- [ ] Deve mostrar arrecadado, custo e diferença por campanha
- [ ] Deve permitir encerrar uma campanha mantendo o histórico acessível

## O problema

Na revisão das telas de 03/09, a coordenação pediu campanhas como tipo de doação: "doação específica pra uma campanha, tipo Adapta ou Natalenço, que têm custo pra nós". Hoje a doação para uma campanha vira doação em dinheiro comum, e ninguém sabe quanto cada campanha arrecadou nem se cobriu o custo.

Não é o item P (metas e campanhas), que a cliente descartou: aqui não há meta nem acompanhamento, só a classificação da doação e o resultado de cada campanha.

## Decisões

- **Mesmo desenho da US-12.** Tabela nova `campaigns` com nome, início, fim previsto (opcional) e custo estimado. A equipe lê, para escolher a campanha na doação; só a coordenação cadastra, altera e apaga.
- **A doação em dinheiro ganha `campaign_id`, opcional.** O formulário ganha "Campanha (opcional)" com as campanhas abertas, ao lado de "Evento (opcional)".
- **Uma doação é de um evento ou de uma campanha, nunca dos dois.** O banco garante com uma restrição (`check`), e a action devolve a mensagem antes. No formulário, escolher um limpa o outro.
- **Arrecadado, custo e diferença vêm da view `campaigns_totals`,** com `security_invoker`, como a `events_totals`. Diferença é arrecadado menos custo: negativa (com sinal de menos, em coral) enquanto a campanha não cobriu o custo.
- **Encerrar não apaga.** Encerrar grava a data em `closed_at`: a campanha sai do formulário de doação e continua na lista, com o total e as doações (quarto critério). Dá para reabrir. Campanha com doação não pode ser apagada (chave estrangeira com `restrict`).
- **A `donations_cash_view` é recriada de novo,** agora com a campanha, mantendo `security_invoker` e as permissões. A lista de doações mostra "Campanha: ..." e a exportação ganha a coluna.
- **O histórico da ficha e o registro original (US-10) mostram a campanha.**
- **Tela em `/doacoes/campanhas`, só da coordenação.** A rota entra em `lib/rotas.ts` e o menu de Doações ganha "Campanhas" depois de "Eventos".
- **Seed:** a campanha "Natalenço 2026" (01/07 a 20/12, custo R$ 800,00) com uma doação de R$ 150,00 da Sônia Maria Reis em 05/07/2026. Julho foi escolhido para não mudar os números de maio e junho que os testes da US-15 e da US-17 conferem.
- **Contribuição, relatório e planilha:** com a US-15, a US-17 e a US-18 na `main`, a doação de campanha já entra na soma das doações em dinheiro. As Partes E, F e G mostram a parte de cada campanha em cada uma delas.

## Como este guia mostra as mudanças

Arquivo novo vem inteiro. Em arquivo que já existe, o bloco mostra só o trecho: linha com `-` sai, linha com `+` entra, e as outras são contexto para achar o lugar.

**O código deste guia foi conferido em 20/10** num ambiente de conferência, com a `main` de 20/10, o código do guia da US-12 e as outras stories desta leva aplicadas: passou em `tsc`, no `npm run lint` e no `next build`. A migração e o seed foram aplicados num PostgreSQL com os papéis do Supabase, e as regras foram conferidas como caixa e como coordenação: a caixa não cadastra campanha e registra a doação vinculada; a doação com evento e campanha juntos é recusada; a campanha com doação não é apagada. Os testes do Playwright não foram executados. Quem implementa roda tudo de novo.

Se a migração da US-12 mudar na revisão, confira a definição da `donations_cash_view` que está na `main`: a desta migração tem de ter as mesmas colunas, mais `campaign_id` e `campaign_name`.

```sql
-- US-13 · Doação vinculada a uma campanha
-- Campanhas do Instituto (Adapta, Natalenço), com período e custo estimado, e
-- doação em dinheiro ligada a uma delas. Mostra arrecadado, custo e diferença.

-- ─────────────────────────────────────────
-- 1. Campanhas. A equipe lê (para escolher na doação); a coordenação cadastra,
--    altera e apaga. Campanha com doação não é apagada: encerra.
--    Encerrar só marca a data (closed_at): o histórico continua acessível.
-- ─────────────────────────────────────────

create table public.campaigns (
  id             uuid primary key default gen_random_uuid(),
  name           text not null check (btrim(name) <> ''),
  starts_on      date not null,
  ends_on        date,
  estimated_cost numeric not null default 0 check (estimated_cost >= 0),
  closed_at      timestamptz,
  created_at     timestamptz not null default now(),
  created_by     uuid default auth.uid() references public.users(id) on delete set null,
  check (ends_on is null or ends_on >= starts_on)
);

alter table public.campaigns enable row level security;

create policy "equipe le" on public.campaigns
  for select to authenticated using (public.eh_equipe());
create policy "coordenacao cadastra" on public.campaigns
  for insert to authenticated with check (public.eh_coordenacao());
create policy "coordenacao altera" on public.campaigns
  for update to authenticated using (public.eh_coordenacao()) with check (public.eh_coordenacao());
create policy "coordenacao apaga" on public.campaigns
  for delete to authenticated using (public.eh_coordenacao());

revoke all on public.campaigns from anon;

-- ─────────────────────────────────────────
-- 2. Doação em dinheiro com campanha, opcional. Uma doação é de um evento ou
--    de uma campanha, nunca dos dois.
-- ─────────────────────────────────────────

alter table public.donations_cash
  add column if not exists campaign_id uuid references public.campaigns(id) on delete restrict;

alter table public.donations_cash
  add constraint donations_cash_evento_ou_campanha check (event_id is null or campaign_id is null);

create index if not exists idx_dcash_campaign_id on public.donations_cash (campaign_id);

-- ─────────────────────────────────────────
-- 3. A view de doações em dinheiro passa a trazer a campanha. Recriada, como na
--    US-12, com security_invoker.
-- ─────────────────────────────────────────

drop view if exists public.donations_cash_view;
create view public.donations_cash_view
with (security_invoker = true) as
select
  d.id,
  d.client_id,
  d.donor_name,
  d.donor_phone,
  d.amount,
  d.frequency,
  d.donated_at,
  d.notes,
  d.created_at,
  coalesce(o.name, '') as origin,
  d.event_id,
  coalesce(e.name, '') as event_name,
  d.campaign_id,
  coalesce(c.name, '') as campaign_name
from public.donations_cash d
left join public.cash_origins o on o.id = d.origin_id
left join public.events e on e.id = d.event_id
left join public.campaigns c on c.id = d.campaign_id;

-- ─────────────────────────────────────────
-- 4. Arrecadado, custo e diferença por campanha. security_invoker: soma só as
--    doações que quem consulta enxerga (a coordenação, todas).
-- ─────────────────────────────────────────

create view public.campaigns_totals
with (security_invoker = true) as
select
  c.id,
  c.name,
  c.starts_on,
  c.ends_on,
  c.estimated_cost,
  c.closed_at,
  count(d.id)::int as donation_count,
  coalesce(sum(d.amount), 0) as raised,
  coalesce(sum(d.amount), 0) - c.estimated_cost as difference
from public.campaigns c
left join public.donations_cash d on d.campaign_id = c.id
group by c.id;

-- Uma view recriada perde as permissões da anterior. Só quem está logado lê.
revoke all on public.donations_cash_view, public.campaigns_totals from anon;
grant select on public.donations_cash_view, public.campaigns_totals to authenticated;
```

```ts
export async function getCampanhasAbertas(): Promise<Campanha[]> {
  const supabase = await createClient()
  const { data, error } = await supabase
    .from('campaigns')

  if (error) throw new Error(error.message)

// Encerrar marca a data; reabrir limpa. As doações e o total continuam valendo.
export async function setCampanhaEncerrada(id: string, encerrada: boolean): Promise<void> {
  const supabase = await createClient()
```

### C2. `actions/campanhas.ts` (arquivo novo)

```ts
'use server'

import { revalidatePath } from 'next/cache'
import { addCampanha, setCampanhaEncerrada } from '@/lib/store'
import { parseMoney } from '@/lib/utils'

const DATA = /^\d{4}-\d{2}-\d{2}$/

function revalidarTelas() {
  revalidatePath('/doacoes/campanhas')
  revalidatePath('/doacoes/dinheiro/nova')
}

export async function criarCampanha(fd: FormData): Promise<{ error: string } | void> {
  const name = ((fd.get('name') as string) || '').trim()
  const inicio = ((fd.get('starts_on') as string) || '').trim()
  const fim = ((fd.get('ends_on') as string) || '').trim()
  const custoDigitado = ((fd.get('estimated_cost') as string) || '').trim()
  const custo = custoDigitado ? parseMoney(custoDigitado) : 0

  if (!name) return { error: 'Informe o nome da campanha.' }
  if (name.length > 80) return { error: 'Use um nome de até 80 letras.' }
  if (!DATA.test(inicio)) return { error: 'Informe a data de início.' }
  if (fim && (!DATA.test(fim) || fim < inicio)) return { error: 'O fim previsto precisa ser depois do início.' }
  if (!Number.isFinite(custo) || custo < 0) return { error: 'O custo estimado precisa ser zero ou mais.' }

  try {
    await addCampanha({ name, starts_on: inicio, ends_on: fim || null, estimated_cost: custo })
  } catch (e) {
    console.error('criarCampanha error:', e)
    return { error: 'Não foi possível cadastrar a campanha. Tente novamente.' }
  }
  revalidarTelas()
}

export async function encerrarCampanha(id: string, encerrar: boolean): Promise<{ error: string } | void> {
  try {
    await setCampanhaEncerrada(id, encerrar)
  } catch (e) {
    console.error('encerrarCampanha error:', e)
    return { error: 'Não foi possível alterar a campanha. Tente novamente.' }
  }
  revalidarTelas()
}
```
