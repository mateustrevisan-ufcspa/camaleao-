# TS-01 · Regras de TypeScript no lint (2 SP)

> Como integrante da equipe, eu quero que o lint reprove código TypeScript com variável não usada ou com tipo `any`, para que esse descuido seja barrado pela esteira, e não descoberto na revisão.

**Tipo:** technical story · **Implementa:** Laís · **Revisa:** Bibiana · **Branch:** `ts-01-lint-typescript` · **Depende de:** nada

## Critérios de aceitação

Propostos no planejamento da Sprint 3. A equipe confirma ou ajusta na abertura da sprint.

- [ ] Deve aplicar no lint as regras de TypeScript do Next (`eslint-config-next/typescript`)
- [ ] Deve reprovar a esteira quando houver variável não usada, como erro e não como aviso
- [ ] Deve deixar o código atual sem nenhum erro e sem nenhum aviso de lint
- [ ] Deve provar o bloqueio com um Pull Request de teste, fechado sem merge

## O problema

Em 02/10 você abriu o PR #7 com uma variável não usada de propósito, e a esteira passou. A causa foi confirmada em 07/10: `eslint.config.mjs` carrega só as regras `core-web-vitals` do Next, que não olham TypeScript.

## O que a conferência deste guia encontrou

Dois fatos, medidos em 09/10 sobre a `main`, que mudam o tamanho da story:

1. **Só acrescentar as regras não resolve.** Com `eslint-config-next/typescript`, a variável não usada passa a aparecer, mas como **aviso**. E aviso não reprova: o `eslint` termina com sucesso e a esteira fica verde. O PR #7 continuaria passando. Tipo `any`, esse sim, já vem como erro.
2. **O código atual não tem nada a corrigir.** Com as regras novas, o lint da `main` termina com zero erros e zero avisos. O mesmo vale com os testes da SEC-03 (PR #11) junto.

Por isso a mudança tem duas partes: a regra de variável não usada vira erro, e o comando de lint deixa de aceitar aviso.

## Decisões

- **`@typescript-eslint/no-unused-vars` como erro.** Nome começando com `_` fica liberado, para o caso raro de um parâmetro que precisa existir e não é usado.
- **`--max-warnings=0` no `npm run lint`.** Qualquer aviso reprova. Como hoje não há nenhum, a regra entra sem custo e impede que avisos se acumulem.
- **Nada de desligar regra para fazer passar.** Se alguma coisa aparecer quando você rodar (o código muda todo dia), corrija o código. `eslint-disable` só com um comentário dizendo o motivo, e isso vai para a revisão.

## 2. `eslint.config.mjs`

Substitua o arquivo inteiro:

```js
import { defineConfig, globalIgnores } from 'eslint/config'
import nextVitals from 'eslint-config-next/core-web-vitals'
import nextTs from 'eslint-config-next/typescript'

export default defineConfig([
  ...nextVitals,
  ...nextTs,
  {
    rules: {
      // No pacote do Next esta regra é só aviso, e aviso não reprova a esteira.
      // Aqui vira erro. Nome começando com "_" marca o que fica sem uso de propósito.
      '@typescript-eslint/no-unused-vars': [
        'error',
        { argsIgnorePattern: '^_', varsIgnorePattern: '^_', caughtErrorsIgnorePattern: '^_' },
      ],
    },
  },
  globalIgnores(['.next/**', 'out/**', 'build/**', 'next-env.d.ts', 'playwright-report/**', 'test-results/**']),
])
```
