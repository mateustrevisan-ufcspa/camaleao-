# US-06 · Busca de pessoa em qualquer tela (3 SP)

> Como voluntária do brechó, eu quero encontrar a ficha de alguém por nome, apelido ou telefone, para que eu nunca precise pedir os dados de novo a quem já é conhecido do Instituto.

**Tipo:** user story · **Implementa:** Alissa · **Revisa:** Laís · **Branch:** `us-06-busca-de-pessoa` · **Depende de:** nada para começar. Os testes da Parte D usam a pasta `tests/acesso`, que chega à `main` com a SEC-03 (PR #11).

## Critérios de aceitação

- [ ] Deve buscar por nome parcial, telefone e apelido
- [ ] Deve retornar resultado em menos de 2 segundos
- [ ] Deve estar disponível no registro de venda e de doação
- [ ] Deve mostrar na lista se a pessoa já comprou ou já doou

## O problema

A busca de pessoa já existe nas telas de nova venda e nova doação, no componente `ClientPicker`. Ela tem quatro limites:

- **Não existe apelido** no cadastro. A coluna nem existe no banco.
- **Não ignora acento:** quem digita "claudia" não acha "Cláudia".
- **Não mostra se a pessoa já comprou ou doou.** A lista mostra só nome e etiquetas.
- **A tela recebe a lista inteira de pessoas**, com todos os dados de cada uma, e filtra no navegador. Funciona com 8 pessoas de exemplo. Com a planilha do brechó importada (US-09), cada abertura da tela de venda mandaria o cadastro inteiro para o navegador.

## Decisões

- **A busca roda no banco.** Uma função, `buscar_pessoas`, recebe o que foi digitado e devolve no máximo 8 linhas, só com o que a lista mostra. As telas de venda e de doação deixam de receber a lista de pessoas.
- **O resultado traz só o final do telefone.** A busca compara o termo com o telefone inteiro, mas devolve os quatro últimos dígitos, para qualquer perfil. Dá para confirmar com a pessoa ("termina em 3344?") sem expor o número. Combina com a SEC-05, que mascara o telefone para o balcão.
- **Telefone só com 4 dígitos ou mais.** Com menos, alguém poderia descobrir números testando um dígito por vez.
- **"Já comprou" e "já doou" olham todo o histórico.** O balcão só enxerga vendas e doações do dia (US-23), mas saber se a pessoa já é conhecida é o objetivo desta story. Sai só o sim ou não, sem valor e sem data. Essa linha entra na matriz de permissões (Parte C).
- **Busca sem acento e sem diferenciar maiúscula.** Usa a extensão `unaccent` do PostgreSQL, que o Supabase já traz.
- **O apelido não entra na `clients_view`.** A SEC-05 recria essa view nesta mesma sprint. Para as duas stories não disputarem a mesma definição, a ficha busca o apelido direto da tabela e junta em `lib/store.ts`.
- **A tela Clientes continua filtrando a lista que já carrega**, agora também por apelido. Trocar essa lista pela busca no banco fica para a ficha única (US-10).

```sql
-- ─────────────────────────────────────────

-- ─────────────────────────────────────────
-- 3. buscar_pessoas: a busca roda no banco e devolve só o que a lista mostra.
--    Antes, as telas de venda e de doação recebiam a lista inteira de pessoas,
--    com todos os dados, e filtravam no navegador.
--
--    security definer, por dois motivos:
--      - compara o termo com o telefone inteiro sem devolver o telefone
--        (só os quatro últimos dígitos saem daqui, para qualquer perfil);
--      - "já comprou" e "já doou" olham todo o histórico. O balcão só enxerga as
--        vendas e doações do dia (US-23), mas saber se a pessoa já é conhecida é
--        o objetivo desta história. Sai só o sim ou não, sem valor nem data.
--    Como a função passa por cima das políticas, a primeira condição do where
--    é public.eh_equipe(): sem perfil ativo, não volta nada.
-- ─────────────────────────────────────────

create or replace function public.buscar_pessoas(p_termo text, p_limite int default 8)
returns table (
  id          uuid,
  name        text,
  nickname    text,
  phone_final text,
  tags        text[],
  ja_comprou  boolean,
  ja_doou     boolean
)
language sql
stable
security definer
set search_path = ''
as $$
  with termo as (
    select
      extensions.unaccent(lower(btrim(coalesce(p_termo, '')))) as texto,
      regexp_replace(coalesce(p_termo, ''), '\D', '', 'g')     as digitos
  )
  select
    c.id,
    c.name,
    coalesce(c.nickname, ''),
    right(regexp_replace(coalesce(c.phone, ''), '\D', '', 'g'), 4),
    coalesce(
      (select array_agg(t.name order by t.name)
         from public.client_tags ct
         join public.tags t on t.id = ct.tag_id
        where ct.client_id = c.id),
      '{}'
    ),
    exists (select 1 from public.sales s where s.client_id = c.id),
    exists (select 1 from public.donations_cash  d where d.client_id = c.id)
      or exists (select 1 from public.donations_items d where d.client_id = c.id)
      or exists (select 1 from public.donations_caps  d where d.client_id = c.id)
  from public.clients c
  cross join termo
  where public.eh_equipe()
    and length(termo.texto) >= 2
    and (
      position(termo.texto in extensions.unaccent(lower(c.name))) > 0
      or position(termo.texto in extensions.unaccent(lower(coalesce(c.nickname, '')))) > 0
      -- Telefone: só com 4 dígitos ou mais, para ninguém descobrir números
      -- testando um dígito por vez.
      or (
        length(termo.digitos) >= 4
        and position(termo.digitos in regexp_replace(coalesce(c.phone, ''), '\D', '', 'g')) > 0
      )
    )
  order by
    -- Primeiro quem tem o nome ou o apelido começando pelo termo.
    (extensions.unaccent(lower(c.name)) like termo.texto || '%'
      or extensions.unaccent(lower(coalesce(c.nickname, ''))) like termo.texto || '%') desc,
    c.name
  limit least(greatest(coalesce(p_limite, 8), 1), 20)
$$;

revoke execute on function public.buscar_pessoas(text, int) from public, anon;
grant  execute on function public.buscar_pessoas(text, int) to authenticated;
```

A função tem `security definer`, ou seja, roda com a permissão de quem a criou e passa por cima das políticas. Por isso a primeira condição do `where` é `public.eh_equipe()`. Se alguém tirar essa linha, a busca passa a responder para qualquer pessoa logada, mesmo desativada. O teste da Parte D confere isso.

```ts
// US-06: a busca tem de responder em menos de 2 segundos.
const LIMITE_MS = 2000

async function buscar(page: Page, termo: string, esperado: string) {
  const campo = page.getByLabel('Buscar pessoa')
  const lista = page.getByTestId('resultado-da-busca')
```
