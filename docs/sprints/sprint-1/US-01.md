# Camaleão Admin

Gestão do Brechó Camaleão e das doações do Instituto Camaleão. Next.js + Supabase.

## Pré-requisitos

| Ferramenta | Versão | Instalação (macOS) |
| --- | --- | --- |
| Node.js | 20 LTS ou mais novo | `brew install node@20` |
| Docker Desktop | qualquer recente | https://www.docker.com/products/docker-desktop |
| Supabase CLI | qualquer recente | `brew install supabase/tap/supabase` |
| Git | qualquer | já vem no macOS |

O Docker precisa estar aberto antes do `supabase start`.

## Subir o projeto do zero

```bash
git clone https://github.com/mateustrevisan-ufcspa/camaleao-.git
cd camaleao-
npm ci
cp .env.local.example .env.local
supabase start        # na primeira vez baixa as imagens (alguns minutos)
supabase status       # copie "API URL" e "anon key" para o .env.local
npm run dev
```

Abra http://localhost:3000 e entre com o usuário de teste local definido em `supabase/seed.sql`.

## Banco de dados

- O esquema vem de `supabase/migrations`, aplicado automaticamente pelo `supabase start`.
- `supabase/seed.sql` cria o usuário de teste; `supabase/seed-demo.sql` cria clientes, vendas e doações de exemplo.
- `supabase db reset` recria o banco local do zero (migrations + seeds).
- Painel do banco local: http://127.0.0.1:54323
- Mudança de esquema: `supabase migration new <nome>` e edite o arquivo gerado. Nunca edite migração já aplicada.

## Variáveis de ambiente

| Variável | Para quê |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL da API do Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Chave pública (anon) do Supabase |
| `E2E_EMAIL`, `E2E_PASSWORD` | Opcional: usuário dos testes de fumaça |

`.env.local` nunca vai para o git. Valores de produção ficam com a coordenação do projeto.

## Comandos

| Comando | O que faz |
| --- | --- |
| `npm run dev` | Servidor de desenvolvimento em http://localhost:3000 |
| `npm run build` | Build de produção |
| `npm run lint` | Análise estática |
| `npm run test:smoke` | Testes de fumaça (login, venda, doação) |

## Como contribuir

Uma branch por história (`us-02-testes-fumaca`), commits começando pelo ID (`US-02: ...`) e um Pull Request revisado por outra pessoa da equipe antes do merge. O plano da sprint está em `docs/sprints/`.

## Problemas comuns

- **`supabase start` falha:** o Docker não está aberto.
- **Porta 54321 ocupada:** `supabase stop --all` e tente de novo.
- **Login recusado:** rode `supabase db reset` para recriar o usuário de teste.
