## Por que Next.js 16, e não um patch

O Next.js 14 está sem suporte de segurança desde 26/10/2025 (última versão 14.2.35), e o 15 sai do suporte em 21/10/2026. Só o 16 continua recebendo correções até a entrega. Fonte: [endoflife.date/nextjs](https://endoflife.date/nextjs) e o [guia oficial de migração](https://nextjs.org/docs/app/guides/upgrading/version-16).

## O que muda no projeto (levantado no código atual)

| Mudança do Next.js 16 | Situação no Camaleão Admin |
| --- | --- |
| `cookies()` e `headers()` só assíncronos | Já resolvido: `lib/supabase/server.ts` usa `await cookies()` |
| `params` e `searchParams` só assíncronos | Nenhuma página usa |
| Node.js 20.9 ou mais novo | Conferir com `node -v` |
| React 19 | Atualizado pelo codemod; conferir tipos `@types/react` |
| `next lint` removido | O codemod troca o script para o ESLint direto; o `.eslintrc.json` da US-03 vira `eslint.config.mjs` |
| `middleware.ts` passa a se chamar `proxy.ts` | O codemod renomeia arquivo e função; roda em Node.js, o que serve para o Supabase SSR |
| Turbopack padrão em `dev` e `build` | `next.config.mjs` está vazio, sem webpack próprio |

## Passo a passo

### 1. Retrato de antes

```bash
git checkout main && git pull
npm audit
npm audit --audit-level=high --json > /tmp/audit-antes.json; echo "saída: $?"
```

Anote no PR quantas vulnerabilidades altas e críticas aparecem.

### 2. Branch isolada e codemod

```bash
node -v                                   # precisa ser 20.9 ou mais novo
git checkout -b us-26-nextjs-16
npx @next/codemod@canary upgrade latest
```

O codemod atualiza `next`, `react`, `react-dom` e os tipos, troca `next lint` pelo ESLint e renomeia `middleware.ts` para `proxy.ts`. Leia o que ele perguntar e aceite as migrações sugeridas.

Atualize também as bibliotecas do Supabase e o ESLint do Next:

```bash
npm install @supabase/ssr@latest @supabase/supabase-js@latest
npm install -D eslint-config-next@latest @types/react@latest @types/react-dom@latest
```

Se o lint ainda reclamar do formato antigo:

```bash
npx @next/codemod@canary next-lint-to-eslint-cli .
```

### 3. Conferir o que o codemod fez

```bash
git diff --stat
git diff package.json
```

- `package.json`: `next` 16.x, `react` e `react-dom` 19.x, script `lint` chamando `eslint`
- `proxy.ts` no lugar de `middleware.ts`, com a função exportada como `proxy`
- `.eslintrc.json` substituído por `eslint.config.mjs`

### 4. Rede de proteção

```bash
npm run lint
npm run build
supabase db reset
npm run test:smoke
npm audit --audit-level=high; echo "saída: $?"     # 0 quer dizer nenhuma alta
```

Se o `npm audit` ainda apontar vulnerabilidade alta em dependência indireta, rode `npm audit fix` (sem `--force`) e repita os quatro comandos. Se só `--force` resolver, pare e registre no PR qual pacote é: isso vira decisão da equipe, não ajuste silencioso.

### 5. Subir

```bash
git add -A
git commit -m "US-26: migra para Next.js 16 e React 19, sem vulnerabilidades altas"
git push -u origin us-26-nextjs-16
```

No corpo do PR, a tabela de antes e depois:
