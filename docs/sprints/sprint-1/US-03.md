# US-03 · Esteira de integração contínua (3 SP)

> Como integrante da equipe, eu quero que cada alteração passe por lint, build e testes antes de ser integrada, para que a evolução do sistema não introduza falhas silenciosas.

**Implementa:** Mateus · **Valida e revisa:** Laís · **Branch:** `us-03-esteira` · **Depende de:** US-02 (testes de fumaça)

## Critérios de aceitação

- [ ] Deve rodar lint, build e testes a cada Pull Request
- [ ] Deve bloquear o merge quando a esteira falhar
- [ ] Deve exigir aprovação de outro integrante antes do merge, conforme a Definição de Pronto
- [ ] Deve rodar também a cada push na main, para que a branch principal nunca fique sem verificação

## Decisões

- **GitHub Actions**, porque o código já está no GitHub e o plano gratuito cobre o volume do projeto.
- **A esteira sobe o próprio Supabase local.** O build e os testes usam a URL e a chave do banco descartável da esteira, então **nenhuma chave real precisa ir para os segredos do GitHub**. A tarefa 2 do Trello vira: confirmar que a esteira não usa chave de produção.
- **Lint precisa de configuração.** O projeto não tem `.eslintrc`; sem ele, `next lint` pergunta qual configuração usar e trava na esteira.

## 2. `.github/workflows/ci.yml`

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  qualidade:
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Dependências
        run: npm ci

      - name: Lint
        run: npm run lint

      - uses: supabase/setup-cli@v1
        with:
          version: latest

      - name: Banco local descartável
        run: supabase start

      - name: Variáveis do banco local
        run: |
          supabase status -o env > supabase.env
          echo "NEXT_PUBLIC_SUPABASE_URL=$(grep '^API_URL=' supabase.env | cut -d= -f2- | tr -d '"')" >> "$GITHUB_ENV"
          echo "NEXT_PUBLIC_SUPABASE_ANON_KEY=$(grep '^ANON_KEY=' supabase.env | cut -d= -f2- | tr -d '"')" >> "$GITHUB_ENV"

      - name: Build
        run: npm run build

      - name: Navegador dos testes
        run: npx playwright install --with-deps chromium

      - name: Testes de fumaça
        run: npm run test:smoke

      - name: Relatório dos testes (só se falhar)
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report
```

Antes de subir, confira no seu terminal os nomes que a sua versão da CLI usa:

```bash
supabase status -o env
```

Se aparecer outro nome no lugar de `API_URL` ou `ANON_KEY`, ajuste as duas linhas do passo "Variáveis do banco local".

```bash
git checkout -b us-03-esteira
git add -A
git commit -m "US-03: esteira com lint, build e testes de fumaça"
git push -u origin us-03-esteira
```

Abra o PR e espere a esteira ficar verde. O nome do check que aparece no PR (`qualidade`) é o que vai na proteção da branch.

## 3. Proteção da main

GitHub > Settings > Branches > Add branch protection rule (ou Rules > Rulesets), para a branch `main`:

- [x] Require a pull request before merging, com **1 approval**
- [x] Require status checks to pass, marcando o check **qualidade**
- [x] Require branches to be up to date before merging
- [x] Do not allow bypassing the above settings

Se o repositório estiver privado (SEC-01), essa tela pede GitHub Pro, gratuito pelo [GitHub Education](https://education.github.com/).
