# US-33 · Custo do evento (3 SP)

> Como coordenadora do Instituto, eu quero informar o custo de um evento quando ele é conhecido, no fim do evento, para que eu veja o arrecadado, o custo e a diferença, como já vejo na campanha.

**Tipo:** user story · **Implementa:** Mateus · **Revisa:** Laís · **Branch:** `us-33-custo-do-evento` · **Depende de:** nada (o rótulo da campanha segue a resposta da Nílian) · **Publica:** quarta 04/11, à noite

## Critérios de aceitação

- [ ] O cadastro e a edição do evento têm o campo Custo (começa em zero e pode ser alterado depois do evento)
- [ ] A tela de eventos mostra arrecadado, custo e diferença de cada evento
- [ ] Só a coordenação altera o custo; teste de acesso confirma que o balcão não altera
- [ ] Na campanha, o rótulo do custo segue o que a Nílian responder
- [ ] Teste de fumaça: custo informado depois do evento muda a diferença

## O que já existe

Retorno da Nílian (coordenação) em 29/10: "o custo de evento ou campanha normalmente é reconhecido no fim do mesmo". Decisão do Mateus no mesmo dia: campo preenchido à mão pela coordenação, sem cálculo pelo sistema.

- **Evento (US-12):** tabela `events` (nome, data, ativo) e a view `events_totals`, que soma as doações em dinheiro do evento. Não tem custo.
- **Campanha (US-13):** a tabela `campaigns` tem `estimated_cost`, e a view `campaigns_totals` mostra arrecadado, custo e diferença. **O custo só é informado no cadastro**: `actions/campanhas.ts` tem só `criarCampanha` e `encerrarCampanha`. Como o custo só é conhecido no fim, esta story também deixa o custo da campanha editável (desvio do cartão, que dizia "editável"; corrigido no Trello em 30/10).

A política `"coordenacao altera"` já existe em `events` e em `campaigns`: só a coordenação altera, e não precisa de política nova.

## Parte A · Migração `supabase/migrations/20261102100000_custo_do_evento.sql`

```sql
-- US-33 · Custo do evento
-- A coordenação informa o custo do evento, em geral no fim dele. A tela mostra
-- arrecadado, custo e diferença, como na campanha (US-13).

-- ─────────────────────────────────────────
-- 1. Custo, começando em zero. Só a coordenação altera: a política
--    "coordenacao altera" da US-12 já vale para a coluna nova.
-- ─────────────────────────────────────────

alter table public.events
  add column if not exists cost numeric not null default 0 check (cost >= 0);

-- ─────────────────────────────────────────
-- 2. Total por evento com custo e diferença. Recriada com security_invoker,
--    como na US-12: soma só as doações que quem consulta enxerga.
-- ─────────────────────────────────────────

drop view if exists public.events_totals;
create view public.events_totals
with (security_invoker = true) as
select
  e.id,
  e.name,
  e.event_date,
  e.active,
  e.cost,
  count(d.id)::int as donation_count,
  coalesce(sum(d.amount), 0) as total,
  coalesce(sum(d.amount), 0) - e.cost as difference
from public.events e
left join public.donations_cash d on d.event_id = e.id
group by e.id;

-- Uma view recriada perde as permissões da anterior. Só quem está logado lê.
revoke all on public.events_totals from anon;
grant select on public.events_totals to authenticated;
```

## Parte D · `lib/custo.ts` (arquivo novo)

Leitura do custo digitado, igual no evento e na campanha.

```ts
import { parseMoney } from '@/lib/utils'

// US-33 · Custo digitado pela coordenação ("150", "1.234,50"). Vazio vale zero.
// Devolve null quando não é um valor de zero para cima.
export function lerCusto(valor: FormDataEntryValue | null): number | null {
  const digitado = typeof valor === 'string' ? valor.trim() : ''
  if (!digitado) return 0
  if (digitado.includes('-')) return null
  const custo = parseMoney(digitado)
  return Number.isFinite(custo) && custo >= 0 && custo <= 10_000_000 ? Math.round(custo * 100) / 100 : null
}

export const AVISO_CUSTO = 'O custo precisa ser zero ou mais.'
```

### `components/donations/custo-editavel.tsx` (arquivo novo)

O mesmo campo serve ao evento e à campanha: mostra o valor com um botão "Alterar", que vira um campo com "Salvar" e "Cancelar".

```tsx
'use client'

import { useState, useTransition } from 'react'
import { formatBRL } from '@/lib/utils'

// US-33 · Custo de evento ou campanha, alterado na própria linha da tabela.
export function CustoEditavel({
  valor,
  rotulo,
  salvar,
}: {
  valor: number
  // Nome acessível do campo, por exemplo "Custo do evento Bazar de primavera".
  rotulo: string
  salvar: (fd: FormData) => Promise<{ error: string } | void>
}) {
  const [editando, setEditando] = useState(false)
  const [erro, setErro] = useState<string | null>(null)
  const [isPending, startTransition] = useTransition()

  if (!editando) {
    return (
      <div className="flex items-center gap-2">
        <span className="text-sm font-display text-ink">R$ {formatBRL(valor)}</span>
        <button type="button" onClick={() => setEditando(true)} aria-label={`Alterar ${rotulo.charAt(0).toLowerCase()}${rotulo.slice(1)}`} className="chip bg-bg">
          Alterar
        </button>
      </div>
    )
  }

  function enviar(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault()
    setErro(null)
    const fd = new FormData(e.currentTarget)
    startTransition(async () => {
      const res = await salvar(fd)
      if (res?.error) {
        setErro(res.error)
        return
      }
      setEditando(false)
    })
  }

  return (
    <form onSubmit={enviar} className="flex flex-wrap items-center gap-2">
      <input name="cost" aria-label={rotulo} inputMode="decimal" defaultValue={formatBRL(valor)} autoFocus className="input-base w-[110px]" />
      <button type="submit" disabled={isPending} className="chip bg-accent-soft text-accent-deep border-accent-soft disabled:opacity-50">
        Salvar
      </button>
      <button type="button" onClick={() => setEditando(false)} disabled={isPending} className="chip bg-bg">
        Cancelar
      </button>
      {erro && <span className="w-full text-xs text-coral font-body">{erro}</span>}
    </form>
  )
}
```
